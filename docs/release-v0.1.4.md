# Open OST2PST v0.1.4

Pre-alpha Windows release fixing large-folder PST Contents Tables and improving verification diagnostics.

## Downloads

- **open-ost2pst.exe** — Windows graphical interface.
- **open-ost2pst-cli.exe** — command-line interface.
- **SHA256SUMS.txt** — SHA-256 checksums for both executables.

## Critical writer fix

Large Table Context Row Matrices are now split on complete row boundaries when they span multiple NDB data blocks. Non-final Row Matrix blocks are padded to the full 8176-byte NDB payload so the next row starts at the next 8192-byte physical block, as required by MS-PST.

The previous behavior chunked Row Matrices like arbitrary binary streams. With the current Contents Table layout, 389 messages fit in one block but 390 messages crossed the block boundary and could become unreadable through libpff. This could make large folders appear to contain no messages even though substantial PST data had been written.

Regression tests now create, write, reopen and count folders containing 389, 390, 447, 448, 1000 and 5000 messages through libpff, covering both the in-memory and disk-streaming writer paths.

## Verification improvements

- Folders are compared by escaped full path instead of positional order.
- The mandatory empty top-level `Deleted Items` folder synthesized by the PST writer is ignored when the source has no folder at that same path.
- Messages are first matched by Internet Message-ID, then by stable metadata, with positional matching retained only as a final diagnostic fallback.
- A missing or reordered message no longer causes every subsequent folder/message to be reported as different merely because array positions shifted.

## Existing large-store protections

- PST physical blocks are streamed directly to a destination-side `.partial` file.
- The full PST image is not retained in RAM during normal conversion.
- Large attachments use temporary payloads and XBLOCK/XXBLOCK data trees.
- Conversion state is checkpointed with low disk I/O in `*.conversion-state.json`.

## Validation

- Python 3.10–3.13 unit suite;
- libpff interoperability suite;
- large Contents Table regression cases at the single/multi-block boundary;
- Windows harness;
- frozen CLI inspect/convert/verify smoke tests;
- frozen GUI self-test.

## Status

This remains a **pre-alpha** release. A PST generated by v0.1.3 from a mailbox containing affected large folders should be regenerated with v0.1.4; the old file should not be treated as a complete archival copy merely because it opens successfully.

The executables are **not Authenticode-signed**, so Windows SmartScreen may display a warning on first launch.
